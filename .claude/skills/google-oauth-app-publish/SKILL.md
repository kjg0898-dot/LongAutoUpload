# Google OAuth 앱 게시 (개인용 도구)

## 언제 필요한가
- Google Cloud의 OAuth 앱이 **게시 상태: 테스트 중**이고 사용자 유형이 **외부**이면, 로그인(refresh token)이 **7일마다 만료**된다.
- **프로덕션**으로 게시하면 계속 유지된다. 단, 6개월 넘게 안 쓰면 만료된다.
- 본인이나 소수만 쓰는 도구는 **구글 심사(검증) 없이** 게시해도 된다.
  - 로그인할 때 "Google에서 확인하지 않은 앱" 경고가 나오는데, **고급 → (앱 이름)(으)로 이동**을 누르면 된다.
  - 확인하지 않은 앱은 사용자 100명까지 쓸 수 있다.

## 비용: 전부 무료
- OAuth 앱 게시: 무료
- GitHub Pages: **공개 저장소면 무료** (비공개 저장소에서 쓰려면 유료 플랜이 필요하니, 페이지 전용 공개 저장소를 하나 따로 만들면 된다)
- API 사용: 각 API의 하루 할당량 안에서는 무료 (예: YouTube Data API 하루 10,000 단위)

## 순서
1. **브랜딩** 페이지에서 앱 이름, 사용자 지원 이메일, 개발자 연락처 이메일을 채운다.
   - 앱 이름 앞뒤에 이상한 문자(` 등)가 없게 한다.
2. 대상 페이지의 **앱 게시** 버튼이 회색이고 "브랜딩 페이지에서 구성을 완료해야 합니다"라고 나오면, **홈페이지·개인정보처리방침 주소**가 빠진 것이다.
   - 이 칸들은 비어 있어도 브랜딩 저장은 되지만, 외부 앱을 게시하려면 필요하다.
   - 회색 버튼에 마우스를 올리면 빠진 항목이 표시될 수 있다.
3. 개인정보처리방침 페이지를 만든다. 아래 `privacy_template.html`의 `{…}`를 채워 GitHub 저장소의 `docs/index.html`로 올린다.
   - 프로그램과 같은 저장소에 둔다면, 받는 zip이나 자동 업데이트에서 `docs/`를 빼둔다.
4. GitHub 저장소 → **Settings → Pages** → Source: Deploy from a branch → Branch: (기본 브랜치), 폴더: `/docs` → **Save**.
   - 1~3분 뒤 `https://<깃허브아이디>.github.io/<저장소>/` 가 열리는지 확인한다.
   - 주소는 소문자로 된다.
5. 다시 **브랜딩** 페이지에서 다음을 넣고 **저장**한다.
   - 애플리케이션 홈페이지: `https://<아이디>.github.io/<저장소>/`
   - 개인정보처리방침 링크: `https://<아이디>.github.io/<저장소>/#privacy`
   - 서비스 약관: 비워 둠
   - 승인된 도메인: `<아이디>.github.io`
6. **대상 → 앱 게시 → 확인**. 검증이 필요하다는 안내가 나와도 심사는 신청하지 않는다.
7. **게시 전에 받은 로그인은 여전히 7일 뒤 만료된다.** 게시한 뒤 프로그램에서 채널(계정)마다 **새로 로그인**한다.

## 메뉴 찾기
- 새 화면: **Google 인증 플랫폼**(Google Auth Platform) → 개요 / 브랜딩 / 대상 / 클라이언트 / 데이터 액세스
  - 바로 가기: `https://console.cloud.google.com/auth/audience`
- 예전 화면: **API 및 서비스 → OAuth 동의 화면**
- 맨 위 검색창에 "OAuth 동의 화면"을 입력해도 된다.
- 프로젝트가 맞는지 맨 위 프로젝트 선택 칸에서 꼭 확인한다.

## 주의
- 개인정보처리방침은 공개 페이지가 된다. 개인 이메일 대신 GitHub Issues 링크 같은 공개 문의처를 쓴다.
- 열쇠 파일(`client_secret*.json`)과 토큰은 절대 저장소에 올리지 않는다(.gitignore에 넣기).
- 실제 사례: LongAutoUpload(YouTube 업로드 정리 도구, 2026-10)에서 이 순서대로 해서 **프로덕션 게시에 성공**했다.
  - 홈페이지·개인정보처리방침·승인된 도메인을 넣기 전에는 '앱 게시'가 회색이었다.
  - GitHub Pages에서 Branch를 고르지 않고(None) Save하면 페이지가 켜지지 않는다. 브랜치와 `/docs`를 모두 골라야 한다.
  - Pages 화면의 Visibility(GitHub Enterprise) 체험판은 필요 없다.
